# 任务说明模板

主控派活时按这些模板写。每份说明都要自包含：接收方没有你的上下文，也看不到之前的对话。

## TASKS.md 格式

```markdown
# TASKS

- [ ] T1 <动作>。完成标准：<可验证的结果>。覆盖验收标准 <编号>。仓库：<仓库名，单仓库可省略>
  - 假设：<查不到而采用的做法>
- [ ] T2 ...
```

勾选状态：`[x]` 通过，`[!]` 达到审查上限或仍无根因。未通过的条目下写明遗留问题。CI 失败的修复追加为 `CI<n>` 条目。

## 实现者说明

通过 `Agent` 派给 `baton:implementer`。

```markdown
用户目标：<一句话>

任务：T<n> <条目原文>

PRD：.baton/<branch>/PRD.md，相关章节 <编号>

要动的文件：
- <路径>：<要做什么>

数据形状：<类型、字段、结构>

采用方案：<方案及依据。按它实现，不要换成别的做法>

仓库规范：<规范入口路径>

检查命令：
- <测试命令，含解释器路径>
- <类型检查、lint 命令>

用户已拍板的取舍：<与本条相关的，没有写“无”>
```

修复轮用 `SendMessage` 发给同一个实现者，写明：哪些意见成立、要怎么修；哪些不成立，不要改。

## Reviewer 首轮说明

写到 `.baton/<branch>/reviews/T<n>.prompt.md`。工程准则由脚本自动拼在前面，不用复制。

```markdown
你是只读代码审查员。按上面的工程准则审查本条改动。

任务：T<n> <条目原文>
PRD：.baton/<branch>/PRD.md，相关章节 <编号>

审查范围：
- 本条改动：`git diff`（未暂存部分，新建文件已由脚本纳入）。读完整 diff 和被改文件的必要上下文。
- 已通过的条目：`git diff --cached`，只作上下文，不审。

要找的问题：
- 本条完成标准没满足的地方。
- 能给出触发路径的 bug。
- 违反工程准则的写法。

用户已拍板的取舍（不算缺陷）：<列出，没有写“无”>

每个问题填 location、problem、trigger。没有问题时 pass=true、blocking 为空。
```

## Reviewer 复审说明

覆盖同一个 prompt 文件，再跑同一命令。脚本会续接上一轮的 Codex 会话。

```markdown
第 <n> 轮复审，范围不变。

已修复：
- <上一轮的 location>：<怎么修的>

不成立，未修改：
- <location>：<理由和证据>

请复审同一范围。
```

## 顾问说明

通过 `Agent` 派给 `baton:advisor`。

```markdown
节点：<a 拆任务 / b 二次打回 / c 排查无根因 / d 终审>
用户目标：<一句话>
PRD：.baton/<branch>/PRD.md，相关章节 <编号>
材料：
- <a：TASKS.md 路径>
- <b：条目原文、diff 范围、两轮审查结论文件路径>
- <c：现象、日志、已排除的假设>
- <d：`git diff --cached` 全量，[!] 条目列表>
用户已拍板的取舍：<没有写“无”>
要回答的问题：<一句话>
```

## PRD 交叉验证说明

写到 `.baton/<branch>/reviews/PRD.prompt.md`。

```markdown
你是只读需求审查员。按上面的工程准则审查这份 PRD。

PRD：.baton/<branch>/PRD.md
需求原文：<用户原话>

对照代码检查：
- 遗漏：需求原文提到但 PRD 没覆盖的点，受影响但没列出的调用方。
- 矛盾：PRD 内部前后不一致，或与现有代码冲突。
- 验收标准：无法用测试、命令或可观察行为验证的条目。
- 方案：有更成熟的现成做法、在绕路、过度设计、保留了兼容层。

不提需求范围外的功能。location 填 PRD 章节号或代码位置，trigger 写会导致什么错误结果。
```
