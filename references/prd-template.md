# PRD 模板

复制到 `.baton/<branch>/PRD.md` 后填写。不适用的节写“无”，不要删节。只写会影响实现或验收的内容。

```markdown
状态：草稿

# <需求标题>

## 1. 目标

<谁>遇到<什么问题>。做完后，<他们>能观察到<什么变化>。

## 2. 范围

做：
- ...

不做：
- ...

## 3. 行为

用户可见的流程、接口契约（请求、响应、事件）、状态变化、错误表现。

## 4. 技术方案

### 4.1 问题本质

一两句话说清要解决的核心问题，以及必须始终成立的不变量。

### 4.2 数据形状

新增或改变的类型、表结构、消息格式。先写形状，再写逻辑。

### 4.3 选型

| 决策点 | 采用方案 | 依据 |
|---|---|---|
| ... | ... | 官方推荐做法、业界通行架构或仓库现有同类实现的出处 |

### 4.4 改动

按模块列出要改的文件、接口和存储。接口或存储变更时，写明所有调用方如何在同一次改动里迁移。用户没有要求兼容时不留兼容层。

### 4.5 跨仓库契约

每个仓库各自要改什么，契约以哪一方为准。单仓库写“无”。

## 5. 风险

哪些部分属于高风险（钱、权限、事务、并发、生命周期，或仓库规范点名的领域），原因是什么。这些条目由主控亲自实现。

## 6. 验收标准

1. <可由测试、命令或可观察行为验证的一句话>
2. ...

## 7. 假设

| 假设 | 采用的做法 | 理由 |
|---|---|---|

## 8. 仓库上下文

- 规范入口：
- 测试命令：
- 类型检查与 lint：
- 解释器或运行环境：
- 提交钩子要求：
- commit 惯例：
- 收尾审查：
- 用户已拍板的取舍：
```
